# Murus Igneus

Independent open-source IPv4 firewall for Devuan 6 Excalibur / OpenRC.

[Download the alpha.11 prerelease](https://github.com/blasterfish7/murus_igneus/releases/tag/v0.3.0-alpha.11): bootable ISO, DEB, guide, SHA256 checksums and original ISO acceptance report.

Includes a native web configuration editor and disk installer, optional FortiGate text-backup import, nftables policies/NAT, VLANs, DHCP server/DNS, IPv4 DHCP WAN client, static routing and confirmed apply/rollback. VPNs include WireGuard and static IKEv2/PSK with strongSwan; two static WANs support ICMP-based failover. Suricata IPS and a ClamAV explicit HTTP download proxy provide experimental UTM integration. HTTPS content inspection and HA are not implemented.

The assistant supports local Ollama/Qwen3 and optional OpenAI Responses API with explicit data-sharing consent and a user-supplied API key. OpenAI is an external hosted service; the client code is open source. Local model/runtime are installed separately. SNMP switch inventory, LLDP/port monitoring and confirmed port up/down remain available. Administration adds TOTP, bounded persistent packet/audit history and an offline signed application package update tool.

Parental control groups named devices by child/profile on the same LAN, with category/service DNS filters, Google SafeSearch, YouTube Restricted Mode, study/night schedules, temporary bonuses, immediate pause and DHCP reservations. Category lists can update automatically with resolver validation and rollback. An explicit IPv6 guard blocks the entire selected LAN through Murus; it is not per-child IPv6 filtering. Optional local reporting shows 24-hour/7-day forwarded IPv4 volumes, hourly trends, parental drops and DNS request/filter aggregates, with CSV and history clearing. DNS requests do not prove visits or time in apps; bytes are not attributed to sites. Data stays local for up to 7 days/50,000 rows/32 MiB.

Alpha.7 completes the Claude review fixes: bounded atomic Basic login throttling (10 errors/60 seconds per IP), expired-attempt cleanup, exceptional rollback recovery, explicit incomplete-recovery results in the GUI/API, corrected console information and tested ISO preservation even when Actions artifact storage is full.

Alpha.8 integrates responsive status polling during service activation and verified idempotent network rollback. Failed undo commands are tolerated only after kernel readback confirms the intended state; real conntrack/forwarding failures remain errors. Configuration changes remain serialized.

Alpha.9 adds a redesigned administration interface with grouped searchable navigation, light/dark themes, responsive layouts and expandable family cards. The dashboard highlights configuration from scratch, optional migration and disk installation. Live console banners show web access instructions; `murus-info` lists actual HTTPS URLs and `murus-install` offers disk installation with exact confirmation and a shared installer lock.

Alpha.10 fixes empty interface setup with a separate kernel NIC inventory, MAC/link/actual addresses, visible reserved management and a Configure action. Data interfaces support static IPv4 or a DHCP WAN client with an automatic gateway, renewal, owned lease cleanup and rollback. The default-route shortcut uses 0.0.0.0/0 and also accepts the 0.0.0.0 alias. The management port (normally eth0) remains dedicated; data WANs use other configured ports. One DHCP WAN is supported; received DNS is reported without replacing system DNS, and static routes/dual-WAN require static ports.

First login requires a new password before configuration or installation, enforced by the API. The web admin and console root use the same root shadow password authority; console passwd changes are recognized by the web, and disk installation preserves the chosen password. Existing separate web credentials migrate explicitly on first password change; starting the package alone does not alter root. Minimum eight characters, no artificial character-class requirements. The protected Anti-lockout HTTPS rule remains visible and independent of data policies; confirmation/automatic rollback remain 90 seconds.

Alpha.11 adds a live dashboard, visual network-port cards and an application Updates page with Ed25519 bundle staging, independent installation worker, package/configuration snapshots and explicit interrupted-job recovery. OS/kernel upgrades and unattended installation remain separate; a trusted signing key and signed release bundles must be provisioned before using web upgrades. See [application updates](docs/UPDATES.md). Published alpha.10 assets remain unchanged. See [alpha.11 installation and bootstrap](docs/ALPHA11.md).

Previous source acceptance: 251 Python tests without skips, 24 Chromium checks, 51 packet checks, four real HTTPS category downloads, a TLS management/transaction-lock fixture and 73 original UEFI ISO checks. The alpha.11 publication pipeline repeats these checks against the final versioned ISO. Includes real DHCP acquisition/renewal/NAT, static rollback, controlled expiry cleanup, missing-server recovery and management access with data denied. The ISO changes its initial password over HTTPS, logs in on console with that password, recognizes a later console password change in web authentication, installs onto a dedicated blank 16 GiB disk and boots independently with the ISO detached using the chosen password. All 28 packaged application files match the tested source. Physical hardware, BIOS/Secure Boot, FortiGate interoperability, hard-power-cut recovery, live OpenAI model quality and complete UTM efficacy/performance are not certified. DNS-based study restrictions retain limits for unknown DoH/VPNs, direct IPs, cache and alternative routes.

No Fortinet code, firmware or assets are reused.
